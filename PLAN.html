bosync — git as a file system

A OneDrive/Google Drive-style virtual drive on Windows, Linux and macOS, where the "cloud" is a Git repository reached over SSH or HTTP. A shallow clone in a per-user temp folder acts as an on-disk proxy; the OS shows it as a cloud-synced drive whose files are cloud-only placeholders. Opening a file re-syncs and hydrates it; saving commits and pushes. Built in (as much as possible) pure Rust.

Backend: Git over SSH / HTTP gix · pure-Rust Git · shallow clone Windows · Cloud Filter Linux · FUSE macOS · File Provider Language: Rust

01 The idea in one paragraph

bosync turns a Git repository into a virtual drive. We do a shallow clone of the repo into a per-user temp folder — that folder is our on-disk proxy for the repo. We then register that folder with the OS as a cloud-synced drive (Cloud Filter on Windows, a FUSE mount on Linux, File Provider on macOS) and mark every entry as cloud-only: names, sizes and icons show in the file manager, but the bytes are not resident. When a user opens a file we refresh the shallow copy, hydrate that file, and let the open proceed. When they save, we sync the change, commit and push it back to the remote, then return to idle. While idle we periodically re-fetch to stay current, prune history to keep the proxy small, and re-dehydrate files that haven't been touched for a few minutes. Listing a folder again triggers a fresh shallow copy so the proxy is always up to date.

06 Key data flows

Open (hydration)

open file.rs → OS: fetch-data(path) → refresh shallow clone → resolve path in proxy → hydrate file bytes → open proceeds

Save (commit + push)

save file.rs → OS: notify-save → sync change into proxy → gix: commit → push origin (ssh) → back to idle

Idle engine

every interval → gix fetch (shallow) to stay current → prune history to keep proxy small → for each file idle > N min: mark cloud-only → on next directory listing: re-trigger shallow copy and serve fresh proxy

07 Milestones

  1. Spike & scaffold

    GOAL: a registered cloud-sync mount that shows up in the file manager.

    Cargo workspace with a platform crate per OS behind one mount trait. Pick the Windows path (cloud-filter vs raw windows) via a throwaway spike; mount an empty proxy folder and log every callback. Prove the plumbing before any Git.

  2. Shallow-clone proxy, read-only

    GOAL: browse a real repo over SSH or HTTP; open files; bytes come from the shallow clone.

    Shallow-clone the repo (gix, depth 1) into the per-user temp proxy, project it as cloud-only placeholders, and hydrate on open. Listing re-triggers a fresh shallow copy. This is the headline demo.

  3. Write-back: commit & push

    GOAL: edit a file in the drive → it becomes a commit pushed to origin.

    On save, sync the change into the proxy, commit through gix, and push over SSH or HTTP; then return to idle. Single branch.

  4. Idle engine

    GOAL: stay current and stay small without user action.

    Background ticks: periodic shallow re-fetch, history pruning to bound proxy size, and re-dehydration of files idle for a few minutes. Listing always serves a freshly synced proxy.

  5. Cross-platform & polish

    GOAL: the same core runs on Windows, Linux and macOS.

    Fill in the Linux (FUSE) and macOS (File Provider) platform crates against the shared trait, conflict surfacing for diverged edits, branding/icon, graceful unmount.

POC stops at M3 (shallow-clone mount + commit/push + idle engine on one platform). M4 (full cross-platform parity + polish) is the stretch goal shown for direction.

09 Proposed project layout

Per repo convention, dependencies point inward (core knows nothing about how it's mounted) and platform-specific sync logic lives in its own crate behind a trait the core declares.

bosync/ ├─ Cargo.toml workspace ├─ crates/ │ ├─ bosync-core/ proxy lifecycle, hydrate/dehydrate, idle engine; declares Mount trait │ ├─ bosync-git/ gix wrapper: shallow clone, fetch, commit, push, prune (SSH or HTTP) │ ├─ bosync-win/ Windows sync logic — Cloud Filter; impl Mount │ ├─ bosync-linux/ Linux sync logic — FUSE; impl Mount │ └─ bosync-mac/ macOS sync logic — File Provider; impl Mount └─ PLAN.html this document

Each platform crate is compiled in only on its target (#[cfg(target_os = ...)] / per-platform workspace members), but all implement the same Mount trait so bosync-core stays platform-agnostic.

10 Risks & open questions

Three platform backends. Cloud Filter, FUSE and File Provider differ in capability and registration. Mitigation: one Mount trait, ship one platform end-to-end (M0–M3) before fanning out in M4.
Re-sync on every open/list. Refreshing the shallow clone on each open and each directory listing can be costly. Mitigation: debounce/cache the shallow fetch, only re-fetch when stale beyond a threshold.
Remote auth (SSH/HTTP). A background process needs credentials: SSH keys/agent, or HTTP(S) tokens/credential helper. Mitigation: prefer gix's pure-Rust transports; fall back to the system ssh or a credential helper as needed.
Pruning vs. shallow depth. Keeping the proxy small (prune history) while staying able to commit/push needs care so we don't corrupt the shallow clone. POC: depth-1 clone, re-clone rather than deep-prune if needed.
Write semantics. Deciding when to commit/push (every save? debounced?) is a design choice — POC: commit + push on save, one commit per save.
Binary/large files. Hydration must bound memory for very large blobs. POC targets text-ish repos; note the limit rather than solve it.
